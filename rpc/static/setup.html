🔒 Peer Authorization

💡 A node's ID is its hex-encoded ed25519 public key. Peers with unknown IDs will be rejected after failing the challenge handshake. Leave blank to allow any authenticated node (challenge-response still required, but no whitelist check).
When disabled, any node can connect as long as they are on the same chain. Enable to restrict connections to a trusted set.
Step 4 of 8
Storage
Choose where chain data is stored and how much disk space to allocate.
Path where LevelDB chain data is persisted. Use an absolute path such as /var/lib/gyds-fullnode on a production server.
Maximum disk usage for chain data. Full node estimates: ~5–10 GB for a fresh start, growing ~1–3 GB/month depending on traffic. The deploy script will warn if available disk space is below this limit.
💡 A storage monitoring script (check-storage.sh) is written by deploy.sh and can be scheduled via cron to alert you when space is low.

Dashboard PIN
Set a PIN to lock your dashboard and private keys from unauthorised viewers. You'll be asked for it each time the dashboard opens or after 5 minutes of inactivity.
🔒 The PIN is hashed (SHA-256) and stored only on your server. It cannot be recovered — choose something you won't forget. If you skip it, you can create one only by running setup again.
Skip PIN setup Leave the dashboard unlocked. A PIN can only be created from this setup wizard.
