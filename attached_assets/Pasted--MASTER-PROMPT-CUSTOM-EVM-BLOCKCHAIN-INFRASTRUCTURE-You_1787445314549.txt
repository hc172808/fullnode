# 5. REQUIRED NODE ARCHITECTURE

Determine whether the following components are required for this specific blockchain.

Do NOT blindly create unnecessary nodes.

Evaluate each one:

## A. Genesis/Bootstrap Node

Must preserve the existing genesis configuration if the network is already initialized.

Do NOT regenerate the genesis configuration unless absolutely necessary.

If regeneration is necessary, STOP and clearly explain the consequences before doing it.

## B. Bootnodes

Provide reliable peer discovery.

Prefer multiple bootnodes for redundancy.

## C. Full Nodes

Provide complete blockchain data and P2P connectivity.

Support:

* Persistent peers
* Static peers
* Peer discovery
* Sync
* Recovery
* Monitoring

## D. RPC Nodes

Provide secure JSON-RPC access.

Support:

* HTTP RPC
* WebSocket RPC where required
* HTTPS through a reverse proxy
* Health checks
* Rate limiting where appropriate
* Restricted RPC namespaces

Never expose private/admin/key-management APIs publicly.

## E. Validator Nodes

Because this is intended to be a Proof-of-Stake network, determine exactly how validators work in this implementation.

DO NOT invent a validator protocol.

Identify:

* Validator client
* Consensus client or consensus module
* Validator key requirements
* Validator registration
* Block proposal
* Voting/attestation
* Finality
* Slashing rules
* Rewards
* Validator lifecycle

Keep validator private keys completely separate from public RPC services.

## F. Light Nodes

Determine whether the current protocol actually supports light nodes.

If it does not, document that instead of creating a fake implementation.

## G. Archive Node

Determine whether an archive node is actually required.

If not required, document why.

## H. Backup RPC

Determine whether a secondary RPC node should be deployed for redundancy.

# 7. VALIDATOR SECURITY

Validator keys are extremely sensitive.

Never:

* Put validator private keys in source code.
* Put validator private keys in public environment variables.
* Send validator private keys through the RPC endpoint.
* Display validator private keys in the dashboard.
* Log validator private keys.
* Commit keys to Git.
* Expose keys through HTTP/WebSocket APIs.

Use secure secret management appropriate for the deployment environment.

Create a documented backup and recovery procedure.
